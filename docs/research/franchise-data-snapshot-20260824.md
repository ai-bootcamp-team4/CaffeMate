# 프랜차이즈 데이터 스냅샷 — 2026-08-24

## 결론

Proposal Agent에는 공식 가맹 안내가 확인된 9개 브랜드만 전달한다. 개인 가맹 대상이 아닌
스타벅스와 커피빈은 경쟁 참고 자료로만 보존한다. 공식 비용을 찾지 못한 브랜드에는 추정
숫자를 넣지 않았다. 정보공개서와 지역별 출점 가능 여부는 아직 연결되지 않았으므로 모든
추천은 조건부 검토 대상이다.

## 데이터 분리

```text
브랜드 구조화 카탈로그
  -> 개인 가맹 여부 필터
  -> 공식 비용의 확인된 범위
  -> Proposal Agent 입력

공식 원문 수집 목록
  -> Vertex AI RAG Engine 수집 대상
  -> 원문 구간과 기준일
  -> 근거 검색과 인용
```

`franchise-brands-20260823.json`은 필터와 계산용이다.
`franchise-rag-sources-20260824.json`은 RAG 수집 메타데이터다. 이번 작업은 원문 수집 목록을
만든 것이며 Vertex AI RAG Engine에 실제 적재하는 작업은 포함하지 않는다.

## 운영 수집 방법

요청 시점마다 웹을 처음부터 검색하는 방식보다 서버가 공식 자료를 미리 수집하는 방식이
적합하다.

```text
공식 본사 페이지·공식 문서
  -> Cloud Run Job 정기 수집
  -> Cloud Storage 원문 보관(수집 시각·해시)
  -> 구조화 파서
  -> BigQuery 브랜드·비용 카탈로그
  -> MCP의 결정론적 필터와 계산

Cloud Storage 공식 원문
  -> Vertex AI RAG Engine 수집
  -> 질문에 필요한 원문 구간 검색
  -> Evidence와 인용 생성
```

구조화 값은 후보 필터·비용 계산에 쓰고, 원문 검색은 조건 설명과 근거 제시에 쓴다. 지역별
출점 가능 여부처럼 본사 확인이 필요한 최신 상태와 사용자가 올린 계약서는 요청 시점의 도구
조회 대상으로 남긴다. 이 작업에서는 정기 수집 Job, BigQuery 적재, Vertex RAG 수집을 실행하지
않았고 입력 카탈로그와 수집 목록까지만 구현했다.

갱신 시에는 기존 파일을 덮어쓰지 않고 기준일이 붙은 새 스냅샷을 만든다. 원문 해시가 바뀌면
구조화 숫자를 다시 검토하고, 테스트를 통과한 세대만 `list_franchise_universe`가 사용한다.

## 비용 데이터 규칙

- `EVIDENCED_FACT`: 공식 페이지나 공식 문서에서 확인한 값만 사용한다.
- `PARTIAL`: 공식 값이지만 임대차·권리금·별도공사 등 총비용의 일부만 포함한다.
- `UNKNOWN`: 공식 비용을 확인하지 못했다. 계산기에 숫자를 넣지 않는다.
- `DECLARED_ASSUMPTION`: 이후 명시적인 계산 가정을 도입할 때만 사용하며 현재 카탈로그에는 없다.
- `NOT_APPLICABLE`: 개인 가맹 추천 대상이 아니어서 가맹비 계산을 적용하지 않는다.

같은 숫자를 최솟값·기준값·최댓값에 넣은 경우는 공식 페이지에 단일 참고값만 있기 때문이다.
이를 시장 가격 범위로 해석하면 안 된다.

`disclosure_status`를 `MISSING`으로 두고, 없는 값을 추측하지 않았다.

## 폐기 조건

다음 중 하나가 확인되면 현재 상태를 폐기하고 새 스냅샷을 만들어야 한다.

- 본사 공식 채널에서 가맹 모집 중단 또는 직영 전환을 공지함
- 공식 창업비 표가 개정됨
- 최신 정보공개서가 현재 비용·로열티와 충돌함
- 지역 출점 승인 조건이 현재 후보를 배제함
